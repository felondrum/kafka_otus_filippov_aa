# План: Kafka Connect JDBC Sink — Fix & E2E Testing

## Текущая ситуация

| Параметр | Значение |
|----------|----------|
| Коннекер | `kafka-connect-jdbc-sink` (Confluent JdbcSinkConnector) |
| Статус | Connector: RUNNING, Tasks: 6/6 FAILED |
| Ошибка | `requires records with a non-null Struct value and non-null Struct schema, but found HashMap value and null value schema` |
| Данные в topic | Plain JSON (HashMap), produced через Spring KafkaTemplate<String,String> |
| Конвертер | `JsonConverter` + `schemas.enable=false` |

## Корень проблемы

**Confluent JDBC Sink Connector не работает с plain JSON (HashMap).**

Он требует Struct value (Kafka Connect Struct) для работы с `pk.mode` и upsert.
Spring KafkaTemplate с `StringSerializer` производит plain JSON string → коннектор видит HashMap, а не Struct.

## Архитектура data flow (текущая)

```
CallMetadataProcessor.processCall()
    ↓
EnrichmentService.enrich() → Map<String, Object>
    ↓
DualWriter.write(enriched)
    ├── writeKafka() → KafkaTemplate.send("transcription.enriched", callId, json)
    │   └── StringSerializer → plain JSON (HashMap)
    └── writePostgreSQL() → JdbcTemplate.update()  ← DualWriter уже работает!
```

## Кто коснётся изменение (Impact Analysis)

### 1. transcription-analyzer (PRODUCER) — МЕНЯЕТСЯ
- `DualWriter.writeKafka()` — produce Confluent JSON format `{"schema":..., "payload":...}`
- **Последствия:** формат данных в topic изменится с plain JSON → Confluent JSON

### 2. reporting-nps (CONSUMER) — НЕ МЕНЯЕТСЯ
- `EnrichedTranscriptionConsumer.consume()` использует `objectMapper.readTree(jsonEvent)`
- **Важно:** `JsonNode` из Jackson поддерживает и plain JSON, и Confluent JSON (schema + payload)
- **НО:** `readTree()` на Confluent JSON прочитает весь объект целиком, включая `schema` и `payload`
- **Риск:** consumer будет искать поля на верхнем уровне, а они в `payload` → **НУЖНО ИСПРАВИТЬ consumer**
- **Решение:** consumer должен извлекать `payload` из Confluent JSON

### 3. kafka-connect (CONSUMER) — МЕНЯЕТСЯ КОНФИГ
- Коннекер: `value.converter=JsonConverter`, `value.converter.schemas.enable=true`
- **Последствия:** коннекер будет читать Confluent JSON и конвертировать в Struct

### 4. e2e тесты — НУЖНО ОБНОВИТЬ
- `kafka-connect-e2e-test.sh` — produce через API → DualWriter → Confluent JSON
- `e2e-bootstrap.sh` — produce через API → DualWriter → Confluent JSON
- **Последствия:** тесты должны работать через API (call-processor), не напрямую в Kafka

### 5. docker-compose.yml — УЖЕ ИСПРАВЛЕНО
- SASL для kafka-connect добавлен

### 6. kafka-connect-init.sh — НУЖНО ОБНОВИТЬ
- Обновить конфигурацию коннектора (schemas.enable=true, pk.mode, insert.mode)

## Варианты решения

### Вариант 1: Изменить DualWriter → Confluent JSON format (РЕКОМЕНДУЕТСЯ)

**Что делать:**
- Изменить `DualWriter.writeKafka()` чтобы производил данные в Confluent JSON format:
  ```json
  {
    "schema": {"type": "struct", "fields": [...]},
    "payload": {"callId": "...", "transcriptionText": "...", ...}
  }
  ```
- Настроить коннекер: `value.converter=JsonConverter`, `value.converter.schemas.enable=true`
- Использовать `pk.mode=record_key`, `pk.fields=call_id`, `insert.mode=upsert`

**Плюсы:**
- Минимальное изменение в коде (только DualWriter.writeKafka)
- Полная совместимость с Confluent JDBC Connector
- Сохраняет upsert semantics
- Не требует изменения docker-compose

**Минусы:**
- Меняет формат данных в topic (plain JSON → Confluent JSON)
- reporting-nps и другие consumers могут потребовать обновления

### Вариант 2: Добавить Kafka Streams transformer

**Что делать:**
- Создать Kafka Streams app, который конвертирует plain JSON → Struct
- Коннекер читает из transformed topic

**Плюсы:**
- Не меняет формат в transcription.enriched
- Изолирует проблему

**Минусы:**
- Требует новый сервис (много кода)
- Изменяет архитектуру

### Вариант 3: Использовать custom SMT (ConvertJsonToStruct)

**Что делать:**
- Написать кастомный SMT для конвертации HashMap → Struct
- Подключить через `transforms`

**Плюсы:**
- Работает в рамках коннектора

**Минусes:**
- Нужно писать и компилировать кастомный код
- Сложно поддерживать

### Вариант 4: Использовать Apache JDBC Connector

**Что делать:**
- Установить Apache Kafka Connect JDBC Connector (free)
- Он работает с plain JSON

**Плюсы:**
- Работает с plain JSON out-of-the-box

**Минусы:**
- Нужно менять docker image / plugin
- Меньше фич чем Confluent

## Принятое решение: Вариант 1 — Изменить DualWriter → Confluent JSON format

### Что проверим

1. **Формат данных в topic** — plain JSON, поля camelCase
2. **Schema таблицы call_transcriptions** — snake_case columns
3. **FK constraint** — call_transcriptions.call_id → call_metadata.call_id
4. **Пользователь kafka-connect-user** — INSERT + SELECT на call_transcriptions
5. **SASL аутентификация** — kafka-connect подключается к Kafka cluster
6. **reporting-nps consumer** — как обрабатывает Confluent JSON (schema + payload)

### Что будем исправлять

#### 1. DualWriter.writeKafka() — produce Confluent JSON
```java
// Было:
String json = objectMapper.writeValueAsString(enriched);
kafkaTemplate.send("transcription.enriched", callId, json);

// Стало:
Map<String, Object> confluentJson = Map.of(
    "schema", buildJsonSchema(),
    "payload", enriched
);
String json = objectMapper.writeValueAsString(confluentJson);
kafkaTemplate.send("transcription.enriched", callId, json);
```

#### 2. reporting-nps consumer — извлекать payload
```java
// Было:
JsonNode node = objectMapper.readTree(jsonEvent);
String callIdStr = node.has("callId") ? node.get("callId").asText() : null;

// Стало:
JsonNode node = objectMapper.readTree(jsonEvent);
// Проверяем Confluent JSON format
if (node.has("payload")) {
    node = node.get("payload");  // Извлекаем payload
}
String callIdStr = node.has("callId") ? node.get("callId").asText() : null;
```

#### 3. Конфигурация коннектора — schemas.enable=true
- `value.converter=JsonConverter`
- `value.converter.schemas.enable=true`
- `pk.mode=record_key`, `pk.fields=call_id`
- `insert.mode=upsert`

#### 4. kafka-connect-init.sh — обновить скрипт деплоя
