## Структура документа

### 1. Overview
- Краткое описание системы и бизнес-цели (из draft.md)
- Архитектурные принципы (EDA, choreography, CQRS)

### 2. System Context (C4 Level 1)
- ASCII-диаграмма: внешние акторы → система
- Актеры: Caller (REST), Admin, Monitoring System
- Связи с внешними системами

### 3. Container Architecture (C4 Level 2)
- ASCII-диаграмма: 4 микросервиса + Kafka + БД + инфраструктура
- **Контейнеры:**
  - call-processor (Spring Boot REST API)
  - fraud-detector (Spring Boot + Kafka Streams)
  - transcription-analyzer (Spring Boot Producer/Streams/Consumer)
  - reporting-nps (Spring Boot Consumer + REST API)
  - PostgreSQL 15
  - Kafka Cluster (3 brokers, KRaft)
  - Schema Registry
  - Prometheus + Grafana + Kafdrop

### 4. Data Flow Architecture
- Диаграмма потока данных: от REST POST до PostgreSQL
- Таблица топиков Kafka (название, тип, ключ, формат, описание)
- Описание каждого потока:
  - `calls.completed` → fraud-detector + transcription-analyzer
  - `calls.metadata` → reporting-nps
  - `calls.fraud-alerts` → reporting-nps
  - `transcription.raw` → transcription-analyzer (Streams)
  - `transcription.summary` → transcription-analyzer (Streams)
  - `transcription.enriched` → reporting-nps + PostgreSQL
  - `customers.profile` → transcription-analyzer (KTable join)
  - `calls.dlq` → мониторинг ошибок

### 5. Component Diagrams (по сервисам)
- **call-processor:** REST endpoint → validation → Kafka producer → topics
- **fraud-detector:** Kafka consumer → Streams DSL/Processor API → State Store (RocksDB) → fraud-alerts
- **transcription-analyzer:** raw consumer → LLM simulation → enrichment → dual-write (Consumer + JDBC Sink)
- **reporting-nps:** Kafka consumer → PostgreSQL → REST API (CQRS read side)

### 6. Infrastructure Architecture
- Docker Compose структура (profiles для разных сценариев)
- Ресурсы (CPU/RAM на контейнер)
- Сеть (Docker network)
- Тоны (volumes для PostgreSQL, RocksDB)

### 7. Security Architecture
- SASL/PLAIN аутентификация на Kafka
- ACL для разделения прав сервисов
- Schema Registry совместимость
- Валидация входных данных (call-processor)
- Защита REST API (Spring Security)

### 8. Monitoring & Observability
- **Метрики Prometheus:**
  - Kafka: lag, throughput, under-replicated partitions
  - JVM: heap, GC, threads
  - Приложение: обработка звонков, ошибки, DLQ
- **Grafana дашборды:**
  - Кластер Kafka
  - Состояние звонков (статусное распределение)
  - Lag потребителей
- **Логирование:** структурированное (JSON), correlation IDs
- **Tracing:** correlation ID через весь пайплайн

### 9. CI/CD Pipeline
- **Stage: Build:** Maven/Gradle, checkstyle
- **Stage: Test:** Unit (Embedded Kafka) → Integration (Testcontainers)
- **Stage: Package:** Docker images (ARM64)
- **Stage: Deploy:** docker-compose up (local), K8s (prod, future)
- **Quality gates:** покрытие тестов > 70%, no critical vulnerabilities

### 10. Deployment Model
- Local development: docker-compose up
- Resource allocation (из load_and_chaos_tests.md)
- Profiles для разных окружений
