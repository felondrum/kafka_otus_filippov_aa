# Fix kafka-connect-e2e-test.sh — Critical Issues

## Problem Summary

4 critical issues found during exploration that will break all tests:

1. **call_id type mismatch**: Table `call_transcriptions.call_id = UUID`, but test produces strings like `e2e-avro-123456`
2. **ExtractField transformation**: Connector expects `value` field in Avro, but schema is flat — connector will crash
3. **Nullable fields**: Avro schema has `string` (not nullable), but test 4/4 sends `null` — Schema Registry will reject
4. **Offset recovery**: Need to verify connector state survives `docker stop` + `docker start`

## Solutions (user confirmed)

1. **A** — Generate UUIDs in test script (`uuidgen` or `openssl rand`)
2. **B** — Wrap Avro schema with `value` field for ExtractField transformation
3. **Fix test** — Remove null values from test 4/4, use valid string values
4. **Verify** — Check connector restart behavior, ensure offsets committed
