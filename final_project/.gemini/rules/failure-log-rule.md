# Правило: Фиксация ошибок и корректировок (Failure Log)

## Обязательное требование

При **любом** исправлении ошибки или корректировке по запросу пользователя **обязательно** заполняйте запись в файле `openspec/failure-log.md`.

## Когда заполнять

Заполняйте failure log в следующих случаях:

1. **Обнаружена ошибка** — код не работает, тест падает, валидация OpenSpec не проходит
2. **Пользователь запросил корректировку** — "убери LLM, сделай синтетическую генерацию", "переименуй компонент" и т.д.
3. **Обнаружено несоответствие** — spec не совпадает с design, tasks не покрывают requirements
4. **Исправлена архитектурная ошибка** — неверный выбор технологии, неправильная структура

## Не заполнять

Не заполняйте failure log для:
- Тривиальных опечаток (пропущенная точка, лишняя строка)
- Переименований без изменения логики
- Форматирования кода

## Как заполнять

Каждая запись = одна ошибка или одна корректировка. Заполняйте **все 5 колонок** по правилам из `openspec/failure-log.md`:

| Колонка | Что писать |
|---------|-------------|
| **№** | Порядковый номер (начиная с 1) |
| **Где** | Файл, change, компонент — укажите конкретный путь |
| **Что было** | Краткое описание проблемы — что произошло не так |
| **Почему неправильно** | Причина — почему это ошибка, а не фича |
| **Как исправили** | Решение — что сделали для исправления |

## Порядок действий

1. **Обнаружили ошибку / получили корректировку от пользователя**
2. **Исправьте ошибку** в соответствующих файлах (spec, design, tasks и т.д.)
3. **На последнем этапе — перед тем как перейти к следующему task или change:**
   - **Откройте** `openspec/failure-log.md`
   - **Добавьте строку** в таблицу с новым номером
   - **Заполните все 5 колонок** чётко и кратко по правилам из failure-log.md
   - **Обновите** дату в секции "История изменений"
4. **Продолжайте работу**

## Важно

- Заполняйте **сразу после исправления**, не откладывайте
- Записывайте **все** исправления — даже мелкие корректировки
- Если исправление затронуло **несколько файлов** — укажите все файлы в колонке "Где"
- Если исправление **меняет spec** — убедитесь, что валидация `openspec validate` проходит
- Failure log ведёт **вся агентская система** — все записи видны всем
- Исходная шапка `openspec/failure-log.md` (заголовки, таблицы, примеры) **не должна меняться** — добавляйте только строки в таблицу и записи в историю

## Где лежит файл

```
openspec/
└── failure-log.md  ← заполняйте здесь
```

## Итог

**Ошибка найдена → Исправили → Записали в failure log → Продолжили работу**

Без failure log — история исправлений теряется. С failure log — прозрачно и понятно.
