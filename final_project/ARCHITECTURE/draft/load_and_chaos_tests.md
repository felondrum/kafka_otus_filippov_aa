# Дополнение к проекту: Нагрузочное и хаос-тестирование (Docker на Mac M1)

## 1. Нагрузочное тестирование

### 1.1. Целевые показатели производительности

Адаптировано для M1 (ARM64):

- **Нормальная нагрузка:** 5000 звонков/час (≈1.4 зв/сек)
- **Пиковая нагрузка:** до 100 зв/сек
- **Сквозная обработка:** < 45 сек (норма), < 90 сек (пик)
- **Lag потребителей:** < 2000 (норма), < 8000 (пик)

### 1.2. Сценарии

| Сценарий   | Интенсивность       | Длительность | Критерии успеха                                 |
|------------|---------------------|--------------|-------------------------------------------------|
| Базовый    | 1.5 зв/сек          | 2 часа       | Lag < 500, CPU < 70%, память < 80%              |
| Пиковый    | 100 зв/сек          | 5 мин        | Lag < 8000, восстановление < 10 мин, нет потерь |
| Длительный | 2 зв/сек            | 8 часов      | State Store < 3GB, нет утечек памяти            |
| С ошибками | 5 зв/сек (5% битых) | 30 мин       | DLQ заполняется, деградация < 25%               |

### 1.3. Инструменты (все совместимы с ARM64)

- **k6** — нагрузочный тест HTTP (нативный ARM)
- **kcat (kafkacat)** — стрельба напрямую в Kafka
- **kafka-producer-perf-test** — встроенный в контейнер Kafka
- **Docker stats** — мониторинг ресурсов
- **Prometheus + Grafana** — сбор и визуализация метрик (ARM образы)

## 2. Хаос-тестирование

### 2.1. Доступные методы (ограничения M1)

- Остановка/перезапуск контейнеров (`docker stop/start`)
- Пауза/возобновление (`docker pause/unpause`)
- Отключение от сети (`docker network disconnect`)
- Ограничение ресурсов (`docker update --memory/--cpus`)

### 2.2. Сценарии

| Сценарий          | Действие                           | Ожидаемый результат             | Время восстановления |
|-------------------|------------------------------------|---------------------------------|----------------------|
| Отказ брокера     | Остановка 1 из 3 брокеров          | Переизбрание лидера, без потерь | < 60 сек             |
| Отказ сервиса     | Остановка call-processor           | Трафик на второй экземпляр      | < 10 сек             |
| Отказ потребителя | Остановка transcription-analyzer   | Rebalance, exactly-once         | < 45 сек             |
| Сбой сети         | Отключение от Docker сети          | Retries, данные не теряются     | < 20 сек             |
| Задержка БД       | Задержка PostgreSQL (через прокси) | Очередь растёт, без потерь      | Зависит от очереди   |
| Hard Shutdown     | Перезапуск Docker Desktop          | Восстановление из томов         | < 3 мин              |

### 2.3. Инструменты

- **Chaos Toolkit** — фреймворк на Python (ARM совместим)
- **Toxiproxy** — прокси для сетевых задержек (ARM образ)
- **Bash скрипты** — управление контейнерами через Docker API

## 4. Критерии успеха (M1)

| Метрика                       | Порог    |
|-------------------------------|----------|
| Lag (норма)                   | < 2000   |
| Lag (пик)                     | < 8000   |
| Сквозная обработка (p95)      | < 45 сек |
| Потеря данных                 | 0%       |
| Ошибки 5xx                    | < 0.1%   |
| Потребление памяти            | < 80%    |
| Время восстановления (брокер) | < 60 сек |

## 5. Требования к инфраструктуре (M1)

### 5.1. Ресурсы Docker Desktop

- **Память:** минимум 12GB (рекомендуется 16GB)
- **CPU:** минимум 4 ядра (рекомендуется 6)
- **Диск:** 50GB свободного

### 5.2. Конфигурация контейнеров

| Компонент                             | Memory | CPU | Образ (ARM)                    |
|---------------------------------------|--------|-----|--------------------------------|
| Kafka (3 шт)                          | 1.5GB  | 1.5 | `confluentinc/cp-kafka:latest` |
| call-processor                        | 1GB    | 1   | `openjdk:21-slim`              |
| fraud-detector                        | 2GB    | 1.5 | `openjdk:21-slim`              |
| transcription-analyzer                | 2GB    | 1.5 | `openjdk:21-slim`              |
| reporting-nps                         | 1GB    | 1   | `openjdk:21-slim`              |
| PostgreSQL                            | 2GB    | 1   | `postgres:15-alpine`           |
| Прочие (Grafana, Prometheus, Kafdrop) | 0.5GB  | 0.5 | ARM образы                     |

**Итого:** ~14GB RAM, ~10 CPU ядер

### 5.3. Оптимизация

- Использовать только ARM64 образы, не эмулировать x86
- Отключать неиспользуемые сервисы (ksqlDB) при тестах
- Использовать `tmpfs` для временных данных (ускорение RocksDB)
- Настроить Docker Compose profiles для разных сценариев

## 6. Отчетность

### 6.1. Отчет нагрузочного теста

- Дата, конфигурация M1
- Количество обработанных звонков
- Latency (p50, p95, p99)
- Максимальный lag
- Пиковое потребление CPU/RAM
- Узкие места и рекомендации

### 6.2. Отчет хаос-теста

- Тип и время инцидента
- Время восстановления
- Потерянные/дублированные данные (0% — успех)
- Действия по восстановлению
- Рекомендации по улучшению устойчивости

### 6.3. Генерация отчетов

- **Скрипт:** `./scripts/generate-report.sh`
- **Отчеты сохраняются в:** `./tests/reports/` с timestamp
- **Формат:** Markdown + JSON для автоматической обработки
